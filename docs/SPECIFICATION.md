# Спецификация HomeVPN Monitor

## Цель

Оператор домашней сети видит, какие узлы из его VPN-подписок отвечают и насколько стабильно они работали. Он сопоставляет результаты и вручную переносит подходящую конфигурацию в HydraRoute.

## Объём первой версии

1. Загружать подписку по действию оператора или расписанию. Первый поддерживаемый формат уточняется после прототипирования.
2. Проверять доступность узлов из домашнего DEV LXC с ограничением параллельности, тайм-аутом и отменой. Использовать заданную оператором тестовую цель.
3. Записывать в SQLite время проверки, итог, задержку успешной проверки и категорию ошибки. Различать успешную, неуспешную и ещё не выполненную проверку.
4. Сохранять историю при переименовании узла. При исчезновении узла из подписки помечать его архивным. Критерии идентичности и срок хранения утверждаются в ходе разработки.
5. Показывать текущее состояние, свежесть результатов и историю в веб-панели. Просмотр и копирование чувствительных настроек доступны по приватному пути. Оператор переносит их в HydraRoute вручную.

## Критерии приёмки MVP

- На синтетических данных воспроизводятся обновление подписки, успешная и неуспешная проверки, тайм-аут, отмена и сохранение истории после перезапуска.
- Из домашнего DEV LXC оператор подтверждает проверку разрешённой подписки и сверяет несколько результатов вручную. Сырые данные остаются внутри DEV.
- Веб-панель различает ошибку и устаревший результат. Доступ через VPS ограничен веб-панелью и не передаёт секреты подписки.
- CI воспроизводится с синтетическими данными и не требует маршрута в домашнюю сеть.
