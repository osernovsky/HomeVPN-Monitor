# Безопасность

## Сообщение об уязвимости

Для сообщений используй приватный отчёт через вкладку Security, если эта функция включена. Если она недоступна, запроси у владельца приватный канал. В публичном Issue допускается только просьба указать канал без подробностей уязвимости и рабочих данных.

## Данные и доступ

- Храни реальные ссылки подписок, данные доступа к узлам, ключи и токены вне репозитория. Это относится также к GitHub Issues, pull requests, артефактам и журналам Actions. Используй синтетические примеры.
- Рабочие конфигурации, результаты проверок и базы SQLite храни в домашнем DEV LXC. Ограничь права на них. Перед публикацией проверяй текст и вложения на секреты.
- Реальные VPN-проверки выполняются только в домашнем DEV LXC. CI работает с синтетическими данными. VPS используется только как reverse proxy веб-панели.
- При удалённом доступе через VPS исключи из проксируемых данных секреты подписок и конфигурации узлов. Для операций с ними используй приватный доступ.
- При утечке отзови или замени скомпрометированные данные и сообщи владельцу приватно. Очистка истории Git сама по себе не отзывает секрет.
